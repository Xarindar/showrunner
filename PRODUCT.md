# Showrunner

## Platform
Web application.

## Product and users
Showrunner is the reusable administration product. Client websites integrate with it; Cottage616 is the beta installation used to validate this content editor.

## Session packages

User-facing agreement labels use **Booking Terms & Conditions**, shortened to **Booking T&C** in compact rows and controls. Existing stored agreement text, billing document types/numbers and booking acceptance behavior stay intact.

Session packages each choose Flat rate or Hourly pricing and their own named hourly rate. Hourly packages replace the flat price input with a saved hourly-rate selector beside Pricing type. Hourly totals use package duration; manual bookings recalculate with the booked duration and snapshot the rate. Existing packages retain their prior session pricing until edited. Session organization tags reuse the media tag picker, including search, selection and new tags, with suggestions from accessible media and session types in the same site.

## Content editing

The published Content overview includes the same Desktop/Mobile preview toggle as the editor. Switching preview size changes the website iframe width without entering edit mode or changing published content.
The Content module opens directly onto a published-site preview with an Edit website action. Website owners enter an editor mode in the same tab, with their actual website in the canvas and a left editing sidebar replacing dashboard navigation. Exit editor restores navigation and keeps unpublished edits during the current visit. Clicking a sidebar section snaps the website preview to it, including repeated clicks. Clicking the preview selects and reveals its matching sidebar entry. Clicking text or an image opens its section and focuses the matching field; text is selected for replacement. They can update approved text, images, and featured services. Site designers own the page sections, layout, and order; customers cannot add, remove, duplicate, or move sections.

The inspector groups fields by the visual item, with its image first. Each header slide has an accordion containing its image, title, caption, and button. Add header creates a slide inside the existing fixed section. The photo or empty image placeholder opens the media picker. The editor hides alternative text, internal location IDs, and SEO fields; accessibility descriptions remain in the site data. Native menus and links let owners switch between registered pages without losing unpublished edits.

Header images offer Adjust framing in the existing admin dialog. Owners move a crop frame over the full photo by dragging or using arrow keys, use Shift for larger keyboard steps, and zoom from 1× to 3×. The frame matches the header's current website preview proportions. Reset centers the image at its original zoom; Cancel discards the dialog's changes, and Apply framing updates the draft. Framing preserves the uploaded original. Responsive headers use larger generated previews when screen size, pixel density or zoom needs them; source resolution still limits detail.

Service selection opens a searchable photo dialog with business and tag filters. Cottage 616 and The Hive remain distinct business filters while booking links retain their configured profiles. Featured cards can inherit the booking photo or choose/upload their own, with independent framing. Framing is available for every editable website photo in the content editor; originals are preserved. Choosing or uploading a website image opens framing automatically. Inspector previews use the current website display proportions and saved framing. The framing dialog reserves its photo canvas before loading.

Buttons offer Page, Service (where booking is configured), and Web address destinations. Existing links remain intact until edited; Web address supports custom links. Service destinations use the service slug and open booking at its next available day. The desktop dashboard panel can collapse to a narrow expand-control rail, and its preference persists across visits. Mobile opens the existing navigation drawer from a floating menu button, with a single page header instead of a second shell header. Editor mode hides this button.

The editor uses open-source Puck inside Showrunner's existing admin shell. Draft edits preview immediately. Mobile editor changes create overrides for only the changed content, including text, links, photos, framing, and editable lists. Desktop values remain unchanged; untouched mobile fields inherit desktop updates. The inspector identifies mobile editing and can restore a section to desktop content. Public sites switch at 720px, including when resized. Publishing uses the existing authenticated, site-scoped content service, revision checks and media library. Successful publication uses the shared admin toast system; confirmations clear after at least five seconds and errors remain until dismissed. Existing Cottage616 content supplies initial values. Cottage616's integration may change to fit the reusable Showrunner workflow.

Header Button settings offer Left, Center, and Right alignment. Mobile edits use the existing overrides so desktop alignment stays independent. The Content overview uses a compact toolbar above its website preview.

## Customer email connection

Settings → Email keeps the page compact and opens setup in the shared modal. Neutral square provider tiles offer Gmail/Google Workspace, IONOS Mail, and Other SMTP, using checked-in transparent brand PNGs and existing admin tokens. Gmail asks whether 2-Step Verification is enabled: Yes opens app-password instructions, while No first guides enabling it. Owners must enter a non-blank app password before advancing, including when editing. IONOS supplies its secure SMTP settings automatically and asks only for the mailbox address/password. Back sits beside step progress; Yes/No and the next action sit in the footer, with the modal X for dismissal. Replies and test emails always use the configured sender address. Send test email checks delivery without changing the working connection; Done saves only after a recent successful test of the unchanged details. No Google OAuth email app, callback, central account, or Showrunner-operated broker is required. Non-marketing messages use the connected sender; marketing retains its existing setup. Saved secrets never return to the browser. See developer-docs/email-provider-setup.md.

## Stack
Next.js App Router, React, TypeScript, Puck, Prisma and PostgreSQL. Websites consume Showrunner's public content API and the shared preview bridge. Existing hosting is Railway.

## Global interface rules
Keep module headers to one compact line: the name, relevant icon/count, and essential actions. Do not add decorative explanatory subtitles or text rows of status metadata beneath the title. Use accessible icons with hover/focus descriptions for compact states and actions; keep full details in settings. Photos use a regular cursor, and image viewers prevent accidental text selection and image dragging.

## Service pricing
Services → Hourly rates manages reusable named USD rates. Session types and included library services choose Flat rate or Hourly; hourly pricing selects a saved rate, and a new rate can be added without leaving an unsaved service. Hourly session/package totals use the selected rate × duration in minutes, rounded once to cents, plus selected add-on charges. Included service prices describe separate add-ons; they do not automatically sum into package totals. Bookings calculate hourly totals on the server and retain the selected rate and agreed total when rates change later. Existing offerings default to flat rate, and existing bookings keep their saved prices. Pricing belongs in Services; Appointments remains the calendar and booking workspace.

## Portfolio
Portfolio manages public website photo albums for showcasing work. Client image delivery, private access, proofing, approvals and download workflows belong to the Clients delivery system, not Portfolio. New Portfolio albums are public galleries saved as drafts. Existing private records remain private; no data migration or deletion is implied.

Service/product showcase cards are an opt-in reusable block inside an approved page section. Owners add cards and bind them to existing catalog records, with display-only and approved client style choices. Names, descriptions, media, product pricing and service duration stay in the central catalog. Service actions reuse slug-based booking; product actions require a configured existing client product destination. See developer-docs/showcase-cards.md.

Package lists use the same shared table system as package services and Suggested Add-Ons: black title/action bars, gray single-line column labels, white rows and quiet borders, with modal editing and hours/minutes duration labels.

## Admin design direction
Intake forms use a visual field builder inside the Forms & Terms workspace: a field palette, an ordered form preview, and settings for the selected field. Text answers, single choices, dropdowns, checkbox groups, and dates use the booking-rule format. Checkbox groups allow multiple selections (or one consent choice); date answers use validated calendar dates. Owners reorder fields with drag handles, keyboard arrow keys, or Move up/down controls. Resize handles and a Field width setting arrange questions at full, half, or third width. Saved layouts render in booking forms and stack on phones. Booking terms retain their text editor and document version checks.

The Shopify-inspired system in DESIGN.md applies across admin navigation, resource indexes, editors and shared controls. Resource types use navigation destinations and continuous editors. Admin owns its tokens independently of tenant settings. Shared controls have one visual implementation; module styles own task-specific layouts. Public routes and client websites retain their own branding. The system and its regression checks are documented in the [admin token developer guide](developer-docs/admin-design-system.md).

Business hours on service creation and editing opens the availability controls from Scheduling rules in a dialog on the current page. Adding or removing hours refreshes the rules without navigating away or discarding the service draft; these hours apply across session types.

Services are added from Add Services inside a package. The library, including search, filters, selection and New service, fills the existing package modal. Creating or editing a service returns to that package; there is no separate What’s included card. Existing unassigned service metadata remains available for assignment from the library view.

Included services use a compact table inside each package. Each row offers Edit to update the service in the same modal. Full descriptions and add-on availability remain in that service editor. The hourly-rate dropdown includes Create New Rate; saving selects the new rate, and Cancel preserves the prior selection.

Reusable services have optional Available as an add-on switches. Off means included-only with no price; on reveals flat add-on pricing or a named hourly rate. Including a service in a package never changes the package total. Suggested Add-Ons is an always-visible compact table of eligible services and their separate prices. A service already included in the selected package is not suggested or charged again. Separate selections add the saved flat price or hourly rate × booked duration; server-side catalog resolution validates names, availability and business ownership. Previously booked snapshots and existing unlinked extra prices remain intact. Checkout presentation of these suggestions is a separate step.

Bookings → Forms & Terms is the site-scoped library for reusable intake forms and booking terms. Each kind has one optional global default. Sessions inherit those defaults, choose a specific document, or explicitly choose none; existing session-specific questions and terms remain supported. Contact name, email and phone are required globally and never configured per session. Forms use text answers, single choice or dropdowns with optional help and required answers. Terms use readable plain text and require acceptance. Editors use shared table-card and modal tokens, with question editing inside the same modal. Saving a library document increments its version and rejects stale edits. Public catalogs resolve the effective documents and return a revision; submission validates required answers, choices and acceptance against that revision. Bookings retain the exact resolved questions, terms, document versions, answers and acceptance timestamp. Jazzr renders the shared questions with site typography and a separate readable terms section. No existing service rules or stored acceptance records are removed.

## Media

Saving file details keeps the inspector open and preserves the current search, folder, filters, page and scroll position. Success appears as a toast; validation errors remain beside the form without discarding edits.

File and folder cards offer Rename, Move, and Delete through a three-dot menu. Renaming files preserves their storage keys and links. Folder rename and move carry the complete nested tree, reject conflicting destinations and require access to every affected item. Delete asks for confirmation: files go to the recoverable archive and files still in use are protected; folders must be empty before removal.

Media home shows folders alongside unfiled assets; opening a folder shows only its direct files and subfolders. Filed assets appear in their own folders rather than being repeated at home. Folders preserve capitals and spaces, open into their direct children, and create new folders within the current path. Search and category filters can find files across folders. Dragging a selection box or using file checkboxes selects multiple files; picking them up shows a floating preview while preserving their grid spaces until a successful drop. Drop on a folder or breadcrumb to move the selection atomically, or use Move to with the keyboard. Cancelled or failed moves restore the files. Grid/list controls sit beside Filters and Sort. Folder creation uses a compact dialog where Enter confirms. Dropping files from the computer opens the upload queue for the hovered folder, or the current folder when dropped elsewhere in the library; the upload dialog shows the destination.
Media is a standalone module for files reused across the business. Open directly into the library, with upload, a wide search field, compact Filters and Sort controls, and removable active-filter chips. Categories, folders, tags and type are available in the Filters popover. Search takes its own row on mobile. Show details on selection. Railway bucket storage is managed infrastructure; users are not asked to choose or configure providers. Storage failures are reported as upload availability errors.

Image selection opens the full authorized image library, with folder and tag filters combined with search. The image browser uses a generous viewport-bounded dialog with visible folder icons, nested-folder breadcrumbs, and automatic loading as owners scroll. Search and tag filters remain available; failed page requests offer an explicit retry. Upload dialogs grow with their contents, centered over the admin working area on desktop and within the viewport on mobile. Use a compact Choose files toolbar, thumbnail rows and clear upload states, without a permanent dashed drop box or separate cards around each file. Batch uploads and drag-and-drop remain available.

Service creation and editing include an always-visible Photos section inside Session details, without a divider or More photos disclosure. The first uploaded image is the larger hero on the left; additional photos occupy two smaller thumbnail rows beside it. Add photos remains visible above the gallery. The first added photo becomes the main photo when none is selected. Extra photos can be used as the main photo or removed. Uploading and selecting reuse the existing media library; selections save with the service. Crop and framing adjustments live in the content editor for the website placement. Existing service crops and separate website photos are preserved. The public services API and client booking flow retain their existing contract; additional images remain in admin until a website integration opts to display them.

## Booking schedules

Each package offers Flat rate, Hourly or Fixed Time Slot in Pricing type. Fixed Time Slot pairs a fixed price with a Same Day / Next Day dropdown first in the row, followed by recurring Start Time and End Time controls. For example, 10:00 PM to 2:00 AM with Next Day reserves four hours from the customer's chosen booking date into the next day in the business time zone. Editing either time automatically selects Next Day when the end is at or before the start; an explicit Next Day selection is retained on later time edits. There are no package calendar dates. Availability and conflicts cover the whole window, including the following day and week boundaries. Business hours can end at midnight; midnight to midnight means a full day. Packages retain their own times and derive their duration. Existing duration-based sessions and booked snapshots are preserved. The public service API continues using the default package. Intake form and Booking T&C appear as rows in the session rules table, initially following global defaults; row actions select a session override or none. Manual admin bookings retain their existing ability to agree on a different time and duration.
Bookings contains Appointments (calendar, list and waitlist), Schedule and Staff. Schedule opens with business weekly hours, followed by upcoming closures and resource, calendar and reminder settings. Staff owns employee profiles, booking status, permission-gated admin account links and each employee's weekly availability inside their roster entry. Each weekday opens a small editor supporting multiple time ranges and copying to selected days. Saving is atomic and rejects stale schedules. Staff and resource schedules remain explicit; business hours do not imply inheritance. Legacy scheduling-rule links redirect to Schedule.

## Time presentation
Show all user-facing times in 12-hour format with explicit AM/PM. Use `formatTime` / `formatDateTime` for dated values, `formatTimeValue` for wall-clock values, and the shared `TimeInput` / `DateTimeInput` controls for editing. Storage, API payloads, calendar coordinates and timezone calculations retain canonical 24-hour values. Each weekly-hours Edit action starts from that day’s saved scoped schedule; toggling Accept appointments off and back on retains the draft time ranges.

The media library accepts images up to 12 MB and MP4, WebM, and MOV videos up to 25 MB on server, S3, or R2 storage. Video details offer native playback and seeking; playback depends on browser codec support. Media type filters distinguish images, videos, and other files. Image-only website fields remain image-only. The filter summary reserves its row so folder navigation does not shift breadcrumbs.

Media details prioritize filename, folder, and selectable tags with search and a New Tag dialog. Editorial details and accessibility are collapsed, with accessibility last. Technical file information opens from an info icon; privacy and focal-point values are preserved without library controls. Delete asks for confirmation and remains recoverable from Archived. Admin textareas cannot be manually resized.

Deleting an empty media folder asks only for confirmation. Deleting a populated folder offers Media Home or an accessible destination outside its own subtree, then moves files and subfolders before removing the folder in one transaction. Subfolder name collisions stop the change without overwriting content.

Cottage616 and The Hive team sections use editable member lists: clients can add or remove members while the site keeps its existing card design. Legacy team text, photos, framing, and mobile overrides are adapted on read and retained on save. Shared admin textarea controls disable resizing even when embedded editor styles request it.

On mobile, navigation opens from the existing module page header beside its title. There is no additional Showrunner bar or floating menu over Save controls; a compact fallback appears only while a route has no page header. Section-header add actions retain a compact 28px visual pill inside a 44px touch target.

The session Active switch lives in Session details for both new and existing sessions. The redundant Status summary card is removed from existing-session editing. New-session activation still validates business hours. New and edit sessions share one builder form; Time Before, Time After, Minimum Notice and Book Ahead sit beneath duration and deliverables in each package modal, with units inside their inputs and no dropdown or availability section. These options apply to every package in the session and retain saved values; business hours remain in Schedule. Existing start intervals are preserved.

Tags appears directly below Active in Session details; there is no separate Organization card. The shared tag picker uses the standard form-label typography and 8px label-to-input gap. Embedded table cards retain the same minimum body height when their first row is added.

Client-facing bookings always require name, email and phone in the shared contact step and public booking API, regardless of session rules or saved sets. Contact labels and requirements do not vary by session. Legacy records and manual admin bookings retain their existing optional-phone contract.

Session configuration shows its details, package tiers and intake/booking settings. Bundles containing that session are managed in Session Bundles, not repeated as a reverse-association section or navigation item in the session editor. Removing that editor section does not delete bundles or their session memberships.

Add-on pricing supports Flat rate, Hourly and Per unit. Per-unit add-ons store a unit cost (for example, Extra photos at $3 per unit); manual bookings accept a positive whole-number quantity and snapshot quantity, unit cost and line total. Included services still do not change package prices, and already-booked snapshots retain their agreed amounts. Public checkout presentation of Suggested Add-Ons remains separate work.

## Client photo sessions

Client profiles list photo sessions in a table. Upload photos opens a dialog requiring a scheduled appointment (including manual appointments), session name, optional description and editable date defaulting to today in the business time zone. Saving creates a private gallery and a Media folder at Clients/client name/session name MM-DD-YYYY. Repeat sessions reuse the saved client folder; folder moves and renames preserve upload destinations. Existing images are not relocated. Private session links deliver session photos; optional purchased photo-selection packages retain their existing allowance, payment and selected-original rules. Shared media pickers mirror direct folder navigation at Media Home; search and filters can span folders.

Client session rows open dedicated client/session detail pages. The client profile never expands uploads, media browsing or delivery controls beneath its session list. Saved processing status covers preview generation, including private client proof sizes, and distinguishes Awaiting photos, Images processing, Ready and Needs attention. Failed or interrupted work cannot silently report Ready; already-saved originals remain recoverable.

Users can create reusable services and add-ons with their own names, prices, and increases to photos, locations and outfit changes. Included services add their effects once; per-unit extras multiply effects by quantity. These combine with the base package and are frozen into each booked session snapshot. A session’s proof gallery can explicitly associate a saved per-unit, one-photo add-on and use the booked included-photo count; pricing is never selected by service name. New proof quotes use the associated add-on’s saved rate, while finalized selections retain their agreed price. Client proofs use a dark branded tile gallery, Select/Selected controls, a compact cart, and swipe/arrow previews. Thumbnails and previews are reduced, watermarked WebP derivatives rather than originals.
