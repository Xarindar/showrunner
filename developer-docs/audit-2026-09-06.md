## Scope and method

Reviewed the repository frontend with the Impeccable detector, the Showrunner product/design documents, content contracts, shared controls, navigation, content state/actions, public rendering, and Cottage adapter. Ran the repository tests, ESLint, TypeScript, dependency audit, JavaScript syntax checks, and browser regressions. No dependencies were added.

Browser coverage: all 20 Showrunner module entry routes (Home, Content, Appointments, Clients, Services, Media, Blog, Portfolio, Forms, Testimonials, Payments, Products, Communications, Billing, Automation, Analytics, Users, Deployments, Help, Settings), plus Cottage Home, Hive, Vendors, and Booking, each at desktop and mobile widths. The local application used the existing beta account and data. The website preview used the beta website's real markup with the changed integration assets intercepted from this checkout for predeployment testing.

The first 48 viewport checks all returned HTTP 200, without page exceptions or document-wide horizontal overflow. They identified the named accessibility defects below. The confirmation checks passed all 48 viewport cases after a targeted correction preserved FullCalendar's existing grid semantics. Draft-only interaction checks cover navigation warnings, page switching, media-dialog dismissal, inspector focus, inactive slides, and mobile menus. Existing site content, bookings, accounts, and payment connections are not changed by these tests.

## Detector interpretation and positive findings

The Showrunner detector reported 164 font-size, 98 color, and 77 radius advisories, plus three font warnings. Its design document explicitly covers only the content editor: treating all other product surfaces or Cottage's fonts as violations of that palette would be incorrect. The blog blockquote rule expresses quotation structure, and the current client-activity marker expresses selection; these are intentional. The onboarding progress-width transition communicates actual completion, not decorative layout motion. The two redundant service-card accents were removed.

The Cottage static detector reported degraded HTML parser support, so its regex findings were not treated as a clean bill of health. Browser axe checks supplied computed contrast and semantic checks instead. Screenshots were inspected together for desktop/mobile; existing beta copy and imagery were preserved.

Existing strengths: trusted manifests, safe-URL validation, authenticated site-scoped saves, revision conflicts and compare-and-swap persistence, locked section order, legacy content adapters, semantic native dialogs, media-library error handling, and cancellation-aware booking links. `npm audit` reported zero known vulnerabilities at audit time.

## Reproduction and limits

- `npm test`, `npm run lint`, `npx tsc --noEmit`, and `npm audit --audit-level=moderate` in Showrunner.
- `node --test test/booking-links.test.mjs` in Cottage; `node --check` for changed scripts.
- `node test/browser-audit.mjs` in Showrunner with `AUTH_STATE` pointing to an authorized browser session and `BASE_URL` to the target. `PLAYWRIGHT_MODULE` may point to an existing Playwright installation. `COTTAGE_SOURCE` optionally supplies local assets for predeployment testing.
- `node test/carousel-accessibility.mjs` in Cottage, using the same installed Playwright; `LOCAL_SOURCE=1` tests checkout assets before deployment. Tests require the configured beta site and its existing content. They do not create bookings or publish content.

The broad route checks cover this beta's populated/empty/disabled states, not every permission, tenant palette, payment-provider interaction, or possible dataset. This is a frontend and integration audit, not a penetration test. Browser Back and tab termination remain governed by browser behavior; the draft guard specifically protects reload/close and normal same-tab links. Manual screen-reader testing, 200% text scaling, additional device classes, and production performance profiling remain coverage limits, not claimed passes.

Impeccable context also reported an unrecognized `PRODUCT.md` platform value (`Web application.`); it correctly used web guidance. Design-context drift was reported without changing the product/design artifacts as a side effect.
