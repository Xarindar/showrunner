# Showrunner refactor — October 25, 2026

This pass consolidates admin feedback, dialog behavior and layout rules, removes unused code, and makes module configuration failures visible and atomic. It preserves the existing scheduling/time work already present in the checkout. No dependency or database migration was added.

## Scope and method

The source inventory covered 526 JavaScript/TypeScript files across app routes, shared components, modules, libraries, shell, client adapters, the public bridge and scripts. Three parallel reviews covered action feedback, spacing/tokens and backend duplication. Shared component call trees, removed exports and persisted compatibility paths were traced before deletion. An independent final review checked the combined changes for data loss, authorization and tenant isolation regressions.

The refactor was compared against a saved copy of the initial dirty working tree using a separate Git index. Excluding tests and documentation, this pass adds 500 lines and removes 1,134: a net reduction of 634 lines. These are source counts, not a measured bundle-size or speed improvement.

## Changes

### One feedback system

- `components/ui/notifications.tsx` and `app/admin/notifications.css` own admin toasts. The unused Toast/ToastRegion component and duplicate CSS were removed.
- Payment setup, calendar rescheduling, scheduling forms, media selections, gallery actions, blog uploads and portfolio completion/error feedback use the shared provider.
- Action-state notifications accept an event identity so a repeated identical error announces after a new submission without replaying on unrelated renders.
- Toast colors use matching foreground/background tokens. Errors persist until dismissed; keyboard focus and hover pause timed notices.
- Field validation, retryable file failures, progress, blocking setup errors and destructive confirmations remain beside the relevant task. Login and public pages retain their separate context.

### Shared spacing and controls

- Native admin disclosure headings share padding, weight and a 44px target. This fixes the inconsistent Staff & resource hours / Add closure spacing.
- Stack layouts share their default 16px gap. Broad nested-summary selectors were narrowed to direct children.
- Shared control tokens replace service-specific field skins and repeated touch dimensions. Touch input text uses a 16px token.
- Duplicate dialog, sheet, feedback, toast, button and unused dashboard styling was deleted. Public site branding and data-driven calendar/crop geometry remain independent.

### One dialog interaction primitive

- Modal, OnboardingModal and the email template editor use the same native Dialog lifecycle for Escape, backdrop gestures, focus and close events.
- Removed the unused Sheet/DialogClose API and duplicated event handlers.
- Actual nested-dialog tests caught a bubbling Escape regression during review; target guards now keep the parent dialog and its draft open when a child closes.
- Shared close buttons retain the 44px touch target.

### Less unused code and fewer accidental imports

- Removed unused hero editing/parser helpers while retaining saved hero normalization and public rendering.
- Removed unused Cluster, ReservedSlot, Feedback, TabLink and dashboard timeline/stat/trend variants after checking callers.
- Client components import the UI components they use directly, avoiding the broad barrel's unrelated server-bound modules.
- Removed an unused booking helper. Updated design-system and dashboard documentation to match the remaining components.

### More reliable backend behavior

- Module installations are authoritative after initialization. Removed the catch-all fallback to stale settings JSON; initialization uses a bulk insert and reread to preserve concurrent choices.
- Settings and module selection now save in one transaction. Existing sites avoid unnecessary synchronization writes.
- An explicit empty module selection retains required modules only. New payment-settings initialization requests default modules explicitly.
- Module health uses an explicit map of the 11 current health modules. Loading/check failures produce a visible warning rather than a healthy result.
- Environment settings use one positive-safe-integer parser. Existing object guards replace duplicate implementations.
- Removed double decoding of already-decoded query errors in nine admin pages. Literal percent signs and encoded-looking text survive intact.

## Contracts intentionally retained

- Persisted Cottage content adapters and credential v1 decryption still have real consumers. Removing them requires an explicit data migration.
- Private uploads and public/derived media have different access policies and storage roles. They were not merged.
- Explicit payment-provider choices still fail closed; existing default-provider selection behavior remains.
- Tenant scoping, public URL contracts, signed access, authentication and financial idempotency remain intact.
- The Showrunner public content bridge and Cottage editor integration file are unchanged and have matching hashes.

## Local environment and remaining limits

Live release verification subsequently exposed an existing coupon-date hydration mismatch: UTC server rendering and a Chicago browser displayed different creation dates. Coupon labels now receive the site's timezone explicitly. `test/payments-hydration-browser.mjs` renders the real workspace in UTC and hydrates it in Chicago and Tokyo; it checks creation and availability labels and reproduces the React hydration error when the previous formatting behavior is restored.

The original local database was behind existing repository migrations, including the service-media `imageFraming` column. Its schema and data were left untouched. Route verification used a migrated clone with payment credentials disconnected; no new migration was authored. The temporary server, database clone, database dump and authentication fixture were removed after verification; the existing server on port 3100 was left running.

At completion of this refactor review, no production deployment, commit, push, payment connection, booking save, email send, publish or live upload had been performed. Live provider behavior and a deployed Railway/Cottage editor session had not been exercised. Review artifacts and detailed logs are in ignored `.tmp/refactor-*` and `.impeccable/review/refactor/` paths. Subsequent release verification is recorded with the deployment and pull request.
